# ADR-002: 공통 코어와 Docker 웹 대시보드

## Context

숭실대학교 LMS 학습 보조 프로그램의 Flet 설치형을 유지하면서 PC에서 웹 대시보드를 호스팅한다. 기존 파이프라인은 나뉘어 있지만 작업 실행과 저장 기능이 GUI 아래에 있고 파이프라인에서도 GUI를 참조한다.

## Decision

- 설치형은 공통 코어 + Flet GUI, 웹은 공통 코어 + 서버 + 별도 웹 프런트엔드로 구성한다.
- 첫 호스트는 사용자의 현재 PC인 Ubuntu 26.04이며 Docker로 실행한다.
- 최초 접속 범위는 LAN의 PC·휴대폰이다. 외부 인터넷 접속은 후속 범위다.
- 처음에는 본인 한 명이 사용한다. 추후 사용자별 LMS 학번 계정을 연결할 소유자 경계를 마련한다.
- 초기에는 로그인 없이 사용한다. 사용자가 편의를 위해 명시적으로 선택한 정책이며, 나중에 인증을 연결할 수 있게 정리한다.
- 브라우저를 닫아도 서버 작업은 계속된다.
- 기존 기능 전체를 웹에 대응한다. 기기 파일 업로드, STT 원문·요약 열람과 다운로드를 포함한다.
- 클립보드 모드는 접속한 브라우저에서 프롬프트 복사와 챗봇 열기로 대응한다. 수동 요약 준비 완료와 자동 요약 완료를 구분한다.
- 작업마다 제출 당시 설정을 고정하고 개별 취소·재시도를 제공한다.
- 다운로드·미디어 변환·STT·요약은 각각 한 번에 한 항목을 실행하며 서로 다른 단계는 동시에 실행한다.
- 서버 재시작 후 대기 작업은 복원하고 실행 중 작업은 중단으로 기록하여 재시도할 수 있게 한다.
- 실패·취소·중단은 공통 상태 체계와 재시도 흐름으로 관리하되 종료 이유는 보존한다.
- 설치형과 웹은 설정·결과를 공유할 필요가 없다.
- 영상 추출은 설치된 Google Chrome과 CDP를 기준으로 한다. Playwright 제공 Chromium으로 확인 없이 교체하지 않는다.

## Consequences

공통 모델·서비스·저장 경계, 단계별 큐, 작업 영속화, 실제 취소와 자원 정리가 필요하다. 로컬 경로 선택·파일 탐색기·클립보드는 웹 환경에 맞는 동작으로 대응한다. 인터넷 공개와 다중 사용자 운영은 별도 결정이 필요하다.

사용자의 과거 테스트에서는 시스템 Chrome만 필요한 코덱을 제공했고 Firefox는 CDP 부재로 사용할 수 없었다. 현재 버전의 코덱 지원과 Docker/headless 실행은 아직 검증하지 않았다. 문서의 headless=False 고정 설명과 현재 GUI의 기본 headless 실행도 검증 후 정리한다.
