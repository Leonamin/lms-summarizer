# ADR-004: 웹 UX 개선과 신규 강의 자동 재생 범위

## Context

[ADR-002](002-core-and-web-dashboard.md)는 "신규 강의 주기 수집"을 이번 구현 범위에서 제외했다.
7단계 운영 마무리 이후 다음 두 가지 개선 요구가 제기됐다.

- 웹 UI의 기본 폰트 크기가 작아 가독성이 낮고, 목록형 정보가 세로 스크롤에 계속 누적되어
  실제 상태 확인이 어렵다. `frontend/src/style.css`는 `"Pretendard"`를 폰트명으로 선언했지만
  `@font-face`/로드가 없어 대체 폰트로 렌더되며, 8~13px 크기가 많다.
- LMS에 주기적으로 새 영상이 올라오는데, 이를 감지해 자동 재생·자동 저장하고 싶다. 영상은 동시에
  1건만 재생되며 재생 시 팝업이 뜨고, 다운로드 작업과 자원을 공유해 교착 위험이 있다.

기존 범위를 바꾸는 요구이므로 결정을 기록한다.

## Decision

- 7단계 이후 개선 작업을 **8단계**로 두고, 타이포그래피·UX/UI 개선(8-A)과 신규 강의 감지·자동
  재생·자동 저장(8-B)을 포함한다.
- 8-A: Pretendard를 **폰트 파일 자체 호스팅**으로 실제 로드하고 타이포그래피 위계·크기를 토큰화한다.
  우선 대상은 **작업 목록·단계 모니터**이며, 목록은 **마스터-디테일 + 컴팩트 표**로 재구성해
  세로 스크롤 누적을 줄인다.
- 8-B: 자동 감지·재생은 **수동 토글(on/off)** 로 켠 동안에만 동작한다. 전체가 아니라 **선택 과목만**
  설정된 주기로 감지하고, 감지 조회는 기존 courses 조회 큐·캐시를 재사용한다.
- 자동 재생의 목적은 **출석·진도 인정과 자동 저장 트리거를 모두** 만족한다. 자동 저장 범위는
  **설정에서 선택**한다(다운로드만 / 다운로드+STT+요약).
- 재생은 **동시 1건**으로 직렬화한다. 재생 자원(Chrome/CDP)은 감지·조회·다운로드와 공유하므로
  단일 슬롯으로 직렬화하고 락 순서를 고정해 큐 간 교착을 만들지 않는다.
- 재생 시 뜨는 팝업은 **유형별로 처리**한다. 이어보기와 "재생 중" 팝업을 DOM으로 구분하고, 실제
  재생 중이 아닌데도 "재생 중"으로 표시되는 LMS 버그에는 대기하지 않고 재생을 진행한다. 다만 같은
  시도에서 팝업이 **3회 이상 반복되면 자동 재생을 일시중지**하고 상태를 기록한다.

## Consequences

- ADR-002의 "신규 강의 주기 수집 제외"와 ADR-003의 자원 직렬화 규칙 일부가 갱신·확장된다.
- 감지 스케줄러·토글, 재생 워커, 중복 감지 기록, 팝업 처리와 3회 반복 예외, 교착 방지 동시성
  테스트가 추가된다.
- Pretendard 자체 호스팅으로 오프라인 LAN·Docker에서도 폰트가 안정적으로 적용된다. 마스터-디테일
  재구성과 타이포 토큰은 디자인 범위가 넓어 완료 판단 기준을 문서로 고정해야 한다.

## Status

Accepted — 2026-09-27 사용자 대화에서 개선 범위와 세부 방향(자체 호스팅, 마스터-디테일, 수동 토글,
선택 과목·설정 주기, 자동 저장 설정 선택, 팝업 3회 반복 시 일시중지)을 확정했다. 2026-09-28 실제 LMS
조사로 재생 시작(`.vc-front-screen-play-btn`)·인트로·이어보기/"재생 중" 팝업(`.confirm-msg-box`,
텍스트 구분) DOM을 확인하고, **재생 시간 기준(끝까지)**·**출석 확인**(학습 상태 확인 버튼 →
`.xnvc-progress-info-attendance-status.attendance`, 타임아웃 시 새로고침)·**Chrome/CDP 단일 슬롯 락
순서**(재생→과목 조회→다운로드)를 정했다. 자동 재생 워커 구현·실제 검증은 남아 있다.
