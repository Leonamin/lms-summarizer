# ADR-001: UI 전면 개편 — 백그라운드 큐 중심 IA로 재설계

## 상태

accepted (2026-09-14)

## 배경

백그라운드 작업 큐 도입(2026-09-14)으로 파이프라인이 항목 단위로 독립 실행되면서 기존 UI 구조와 충돌:

1. **진행 모달이 워커를 죽임** — 모달 닫기가 취소로 처리됨. 백그라운드 큐와 모순
2. **단계 UI가 시간 축 모델** — 1→2→3 타임라인 스텝퍼는 일괄 처리 시절 모델. 현재는 각 단계가 독립 워커이므로 "단계별 적체량"이 맞는 표현
3. **사이드바 수직 스크롤 과밀** — 계정+AI+STT+경로가 한 컬럼에 4개 접기 섹션
4. **시작 단계 선택기가 복잡도 원인** — URL/파일 입력 소스 선택과 파이프라인 단계가 섞여 있음. 단계는 입력 소스에서 자동 유추 가능

## 결정

1. **진행 모달(ProgressModal) 폐기** — 작업은 QueueManager가 소유, UI는 구독자. 파이프라인 모니터는 메인 화면 상주 패널
2. **단계별 적체량 표시** — `⬇ 다운로드 [2] → 🔄 변환 [1] → 🎙 STT [0] → 🤖 요약 [3]` 형태. 클릭 시 해당 단계 항목 목록
3. **사이드바 탭화** — 계정 / AI / STT / 일반 4탭, 한 번에 하나만 표시
4. **입력 소스 카드 2개** — LMS URL 카드 / 파일 카드(드래그앤드롭). 확장자로 시작 단계 자동 유추 (.mp4→변환, .wav→STT, .txt→요약). 시작 단계 드롭다운(StageSelector) 폐기
5. **메인 화면 목적 재정의** — 1차: 작업 넣기, 2차: 작업 보기

## 결과

- 삭제: progress_view.py, stage_selector.py, 기존 좌/우 패널 대부분
- 신규: Sidebar(탭), SourceCard×2, PipelineMonitor(적체량), 확장 QueuePanel
- QueueManager는 이미 UI와 분리돼 있어 소폭 수정만 필요 (닫기≠취소는 자동 충족)

## 대안 (기각)

- 탭 전환형 입력 소스: 현재 LectureSection과 유사해 개선 효과 제한적. 카드가 소스 차이를 더 명확히 표현
- 단계적 개편: 모달/단계선택기/사이드바가 서로 결합돼 있어 부분 개편 시 중간 상태가 더 혼란스러움
