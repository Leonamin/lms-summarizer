# 공통 코어 분리 및 웹 대시보드 상세 구현 계획

## 목적과 현재 상태

공통 코어를 사용하는 설치형과 Docker 웹 대시보드를 제공한다. 확정 정책은 [ADR-002](../decisions/002-core-and-web-dashboard.md), 진행도는 [TODO](core-web-dashboard-todo.md)를 따른다.

1단계 기능 조사·기술 계약·Docker Chrome의 실제 LMS 로그인/CDP 검증을 완료했다. [1단계 계약](../logs/2026-09-27-core-web-stage1-contract.md)과 [ADR-003](../decisions/003-web-runtime-and-job-contract.md)에 기술·정책 선택을 기록했다. 2단계 코어 분리를 완료했다([구현·검증](../logs/2026-09-27-core-web-stage2.md)). 영속 작업 실행기·제품 웹 구현은 미착수다. 실제 강의 전체 다운로드·STT·요약은 후속 단계에서 검증한다. 아래 초기 제안 중 구체화된 부분은 1단계 계약을 따른다.

## 범위

첫 버전은 기존 활성 기능 전체, 기기 파일 업로드, 원문·요약 열람, 개별 취소·재시도, 재시작 복구를 포함한다. Ubuntu 26.04 Docker, LAN PC·휴대폰, 인증 없는 개인 모드가 대상이다. 설치형과 웹 데이터는 분리한다.

인터넷 공개, 실제 다중 사용자 운영, 로그인 화면, 신규 강의 주기 수집은 이번에 확정된 구현 범위가 아니다. 추후 인증과 사용자별 LMS 계정을 연결할 경계는 마련한다.

## 제안하는 구조

공통 코어는 과목·강의·작업·시도·단계·산출물·설정 모델과 LMS 조회, 작업 제출·취소·재시도·조회, 스케줄링, 이력·결과 서비스를 제공한다. Chrome/CDP·다운로드·PyAV·STT·요약 공급자는 실행 어댑터로 연결한다. 설정·자격 증명·캐시·작업 상태·산출물 메타데이터는 저장 경계로 분리한다.

데스크톱은 Flet 갱신·파일 선택·탐색기·클립보드·번들 초기화를 맡는다. 웹은 서버 앱 수명·API·업로드·다운로드·이벤트·사용자 컨텍스트를 맡는다. 프런트엔드는 입력·과목 선택·큐·단계 모니터·원문·요약·설정을 제공한다.

디렉토리와 패키지명은 단계 1에서 확정한다. 코어는 GUI와 웹 프레임워크를 import하지 않고 화면·HTTP 요청 객체를 받지 않는다. 설치형은 코어 직접 호출을 유지할 수 있으며 HTTP 서버를 요구하지 않는다.

## 작업·상태·재시도

제안 모델: 안정적인 작업 ID, 소유자 ID, 입력 종류·참조, 제출 설정, 시도 번호, 현재 단계, 상태, 오류 코드·설명, 시간, 산출물 참조. 작업·시도·단계 기록을 구분해 재시도 전 오류와 결과를 보존한다. API 상태 값과 한국어 표시 이름은 분리한다.

기본 상태는 대기·실행 중·완료·실패·취소·중단이다. 실패·취소·중단은 공통 종료·재시도 흐름을 사용하되 종료 이유를 보존한다. 취소 요청과 실제 취소 완료를 구분한다. 수동 요약 준비 완료는 자동 요약 완료와 구분한다.

재시작 시 대기를 복원하고 실행 중 시도를 중단으로 기록한다. 자동 단계 재개는 확정 요구가 아니다. 재시도 시작 단계·산출물 재사용·원본 삭제 후 재다운로드/재업로드 흐름은 단계 1에서 결정한다.

동일 작업 중복 실행을 막고 시도 식별자로 늦은 결과가 새 시도를 덮어쓰지 않게 한다. 제출 설정을 고정하되 비밀 값의 복제·보관과 키 변경·삭제가 재시도에 미치는 영향은 별도 정책으로 정한다.

## 단계별 동시 실행과 취소

다운로드 → 미디어 변환 → STT → 요약에 각 큐와 실행 슬롯 1개를 둔다. 슬롯은 서로 독립적이며 같은 작업은 선행 산출물이 확정된 뒤 다음 단계로 이동한다. 영상 4개에서 다운로드·변환·STT·요약이 서로 다른 영상을 동시에 처리할 수 있다.

단계 완료 저장과 다음 큐 등록 사이 장애로 중복·유실이 생기지 않게 전이와 복원을 설계한다. STT 모델은 동일 설정에서 재사용하고 설정 변경 시 교체한다. 큐 제한·디스크 여유·모델 메모리·API 제한을 고려한다.

현재 취소는 대기만 중단하고 연산 스레드를 남길 수 있다. 단계별 협력 취소 또는 프로세스 종료 방식을 선택한다. 취소 뒤 다음 단계 진입을 막고 임시 파일·브라우저·GPU 자원을 정리한다. 이미 전송한 외부 API 요청의 취소 한계도 기록한다.

## API·파일·이벤트

API 기능은 설정, 과목·강의 조회, 업로드, URL/파일 작업 제출, 작업 목록·상세·단계 적체량, 개별·전체 취소, 재시도, 원문·요약·프롬프트 조회, 산출물 다운로드, 서버 상태·버전·진단으로 나눈다. 구체적인 URL과 전송 기술은 미정이다.

재접속 시 전체 현재 상태를 조회해 이벤트 유실을 보완한다. 구독 해제는 취소가 아니다. 이벤트·로그는 작업·시도·단계에 연결하고 비밀 값과 민감한 다운로드 URL 노출을 정리한다.

업로드는 스트리밍 저장, 크기·유형·용량 검증을 제공한다. 클라이언트 경로를 서버 경로로 사용하지 않고 파일 ID로 접근한다. 작업·시도별 공간으로 동일 파일명 충돌을 막는다. 업로드 실패·취소 파일과 중간 파일 정리 정책을 정한다. 결과 텍스트·Markdown 렌더링 방식을 명시한다.

인증 없는 초기 모드는 기본 개인 사용자 컨텍스트를 사용한다. 이후 인증을 연결할 수 있게 서비스와 저장 접근에 소유자를 전달한다. 인터넷 공개 설정은 이번 배포에 포함하지 않는다.

## 단계별 구현 계획과 완료 기준

### 0. 계획 기록

ADR·상세 계획·TODO를 연결한다. 완료 기준: 확정·제안·미정이 구분되고 진행도 문서가 존재한다.

### 1. 기능 조사·환경 검증·기술 계약

활성 기능과 호출 경로를 목록화한다. 프런트엔드/API/DB/이벤트 기술, 모델·API 계약, 취소·재시도·보관 정책을 결정한다. Ubuntu Docker에서 Google Chrome 로그인·CDP URL 추출을 먼저 확인한다. headless 문서와 코드 불일치를 검증 결과로 정리한다.

완료 기준: 모든 활성 기능에 웹 대응·검증 항목이 있고 구현 계약이 정해진다. Chrome 컨테이너 실행 가능 여부와 환경 제약을 확인한다. 실제 계정·키가 필요한 검증의 준비 여부를 기록한다.

### 2. 공통 모델·설정·저장 분리

과목 모델·프롬프트·단계·상태·검증을 분리한다. 설정·자격 증명·경로·캐시·이력 저장 경계를 마련한다. 파이프라인의 GUI 참조·전역 설정 조회를 제거하고 의존성·진입점을 나눈다.

완료 기준: Flet 없이 코어를 import·사용하고 경로·설정을 명시적으로 전달한다. 설치형 기존 설정·캐시·이력 보존 정책이 적용된다.

### 3. 영속 작업·독립 단계 실행기

작업·시도·단계 저장, 네 큐, 설정 고정, 개별·전체 취소, 재시도, 복구, 산출물 관리, 모델 재사용, 조회·구독 인터페이스를 구현한다.

완료 기준: 단계 간 동시 실행과 단계당 1개 제한을 확인한다. 대기·실행 중 취소, 실패 재시도, 설정 변경, 서버 재시작에서 중복·유실·늦은 결과 덮어쓰기가 없다.

### 4. 설치형 연결

Flet을 공통 서비스에 연결하고 화면 갱신·OS 기능을 GUI에 둔다. 활성 호출 경로 확인 후 중복 워커를 정리하고 PyInstaller·macOS/Windows 빌드를 갱신한다.

완료 기준: 기존 기능과 설정 호환 회귀 및 빌드 확인. 실행 불가능한 대상 OS 검증은 미완료로 표시한다.

### 5. 웹 최소 흐름·Docker

서버가 실행기를 소유한다. 기본 개인 사용자, 설정, 업로드, 제출·조회·취소·재시도, 결과 열람·다운로드와 Docker Compose·볼륨을 구현한다.

완료 기준: 업로드→처리→원문·요약 열람이 동작한다. 화면 닫기·새로고침·재접속은 작업에 영향을 주지 않는다. 컨테이너 재생성 뒤 설정·결과·복구 상태가 유지된다.

### 6. 전체 기능 웹 대응

LMS 조회·URL 처리, 모든 공급자·설정, 프롬프트, 캐시·이력, 클립보드 대체, 모니터·로그, PC·휴대폰 화면을 완성한다.

완료 기준: 기능 대응표 전체에 구현 위치·검증 결과가 있다. 공급자 실제 키 검증과 대체 검증을 구분하고 미확인 항목을 기록한다. 수동 준비를 자동 완료로 표시하지 않는다.

### 7. 대상 PC 운영·배포 마무리

Ubuntu 26.04 LAN PC·휴대폰에서 Chrome, CPU/GPU, 모델 캐시, 디스크 용량, 장시간 실행, 취소·오류·복구, 종료·업데이트를 확인한다. 설치·시작·중지·백업·복원·업데이트·문제 해결을 문서화한다.

완료 기준: 필수 기능 누락과 미해결 항목이 없고 운영 절차를 재현한다. 미검증·기술 제한은 명시한다.

## 진행 규칙

실제 완료만 TODO에 체크하고 단계마다 검증 근거·미해결 항목을 기록한다. 완료 기준 통과 시 다음 단계로 진행한다. 필수 검증이 막혔으면 부분 완료로 남긴다. 제품 범위를 바꾸는 결정은 사용자 확인 후 ADR에 반영한다. 단계마다 반복 승인을 요구하지 않는다.

## 초기 설계 과제와 결정 상태

- 프런트엔드·서버·DB·실시간 전송 기술, 패키지 구조·API 계약.
- 취소의 실제 실행 방식, 외부 API 취소 한계와 timeout·재시도.
- 재시도 시작 단계·산출물 재사용·원본 삭제 시 복구.
- 비밀 값 저장·응답·설정 고정 방식, 설치형 기존 데이터 마이그레이션.
- 업로드 형식·크기·용량, 원본·중간 파일·로그 보관 한도.
- Docker Chrome/headless·화면 필요 여부, 실제 GPU 유무·컨테이너 전달.
- 서버·워커 프로세스 구성과 종료 대기 정책.

위 항목의 구현 기준은 1단계 계약에서 구체화했다. 호스트는 AMD 내장 GPU로 확인하여 초기 STT는 CPU 기준이다. 실제 LMS 로그인·CDP는 제공된 강의 한 개에서 확인했다. Playwright 제공 Chromium 코덱 비교는 미검증이다.
