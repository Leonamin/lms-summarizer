# 신규 강의 감지·자동 재생·자동 저장

7단계 이후 개선 작업(8단계)의 항목 2 상세 계획이다. 웹 대시보드에서 LMS에 주기적으로
새로 올라오는 영상을 감지해 자동 재생 큐에 넣고 자동 저장(다운로드·파이프라인 제출)까지
연결한다. 상위 구조는 [상세 계획](core-web-dashboard-plan.md), 결정은 [ADR-004](../decisions/004-auto-play-and-ux-improvements.md)를 따른다.

## 배경과 요구

- LMS에는 주기적으로 새 영상이 올라온다. 사용자가 매번 목록을 확인하지 않아도 신규 영상을
  감지해 자동 재생할 수 있어야 한다.
- 영상은 **동시에 1건만 재생** 가능하다. 재생 자원(Chrome/CDP)은 다운로드·조회와 공유하므로
  동시 실행을 직렬화해야 한다.
- 영상 재생 시 가끔 이전 재생 지점 안내 또는 "지금 재생 중인 영상이 있습니다" 팝업이 뜨며
  재생이 멈춘다. **HTML/DOM 파싱이 가능한지 확인**하고, 가능하면 파싱해 처리한 뒤 재생한다.
- 감지 후 자동 저장(다운로드 및 후속 처리)을 큐에 넣을 때, 이미 진행 중인 다운로드·감지 작업과
  **충돌하거나 교착(데드락)이 발생하지 않아야 한다.**

## 확정 사항

2026-09-27 사용자 확인으로 다음을 확정했다([ADR-004](../decisions/004-auto-play-and-ux-improvements.md)).

- **실행 방식**: 수동 토글(on/off). 서버가 항상 자동 감시하지 않고, 사용자가 켠 동안에만 감지·재생한다.
- **감지 대상·주기**: 전체가 아니라 **선택한 과목만** 감지하고, 주기는 **설정값**으로 둔다(기본값은 구현 시 정함).
- **자동 재생 목적**: 출석·진도 인정과 자동 저장 트리거를 **둘 다** 만족한다.
- **자동 저장 범위**: 설정에서 선택한다(다운로드만 / 다운로드+STT+요약). 제출은 기존 작업 큐·설정 고정·재시도 체계를 그대로 사용한다.
- **동시 재생**: 1건.
- **팝업 처리**: 유형별로 처리한다.
  - 이어보기(재생 지점) 팝업과 "재생 중" 팝업을 DOM으로 구분한다.
  - LMS 버그로 **실제 재생 중이 아닌데도 "재생 중"으로 표시**되는 경우가 있다. 이 경우 대기하지 않고 재생을 진행한다.
  - 다만 이 예외가 다른 작업과 충돌해 교착이 될 수 있으므로, 같은 재생 시도에서 팝업이 **3회 이상 반복되면 자동 재생을 일시중지**하고 상태를 기록·표시한다.

## 목표

- 선택 과목 신규 강의 감지, 자동 재생 큐, 설정 기반 자동 저장, 팝업 처리와 3회 반복 예외,
  큐 간 교착 방지, 재시작 복구를 제공한다.

## 설계 방향 (제안)

### 감지 스케줄러 (토글·선택 과목)

- 토글이 켜진 동안 설정 주기로 선택 과목·주차를 조회해 마지막 확인 이후 새 강의(강의 ID 기준)를 찾는다.
- 이미 처리·제출한 강의 ID는 기록해 중복 감지·중복 제출을 막는다.
- 감지 조회도 기존 courses 조회 큐/캐시를 재사용해 로그인·CDP 자원을 추가로 만들지 않는다.

### 자동 재생 큐

- 재생 요청은 **단일 슬롯** 큐로 넣어 동시에 1건만 재생한다.
- 다운로드·조회와 같은 Chrome/CDP를 쓰므로 슬롯 배정 순서를 고정하고 큐 간 대기 그래프를 만들지 않는다.
- 슬롯 점유에는 시간 제한을 두어 락이 영구 대기하지 않게 한다.

### 팝업 처리와 반복 예외

- 이어보기 팝업과 "재생 중" 팝업을 DOM 선택자로 구분해 처리한다.
- "재생 중" 오표시(실제 재생 아님)에는 대기하지 않고 재생을 진행한다.
- 같은 시도에서 팝업이 3회 이상 뜨면 재생을 중단하고 자동 재생을 일시중지한다. 중복 감지·제출도 멈추고
  사용자에게 상태를 표시한다.

### 자동 저장 (설정 선택)

- 설정값에 따라 다운로드만 하거나 다운로드+STT+요약까지 제출한다.
- 감지로 만든 작업은 기존 작업 큐·설정 고정·재시도 체계를 그대로 사용한다.

### 교착 방지

- 감지·재생·다운로드가 공유하는 자원과 락 순서를 단일 규칙으로 정한다.
- 한 작업이 다른 큐의 결과를 기다리며 서로 점유하는 구조를 금지한다.

## 완료 기준

- 토글을 켠 동안에만 선택 과목의 신규 강의가 설정 주기 내에 감지되고, 같은 강의를 중복 감지·제출하지 않는다.
- 자동 재생 큐가 동시 1건을 지키고, 팝업을 유형별로 처리한 뒤 재생한다.
- 팝업이 3회 이상 반복되면 자동 재생을 일시중지하고 상태를 기록·표시한다.
- 자동 저장이 설정 범위(다운로드만/전체)대로 동작하고 진행 중 다운로드와 교착이 없다.
- 서버 재시작 후 토글·감지 기록·큐 상태가 복구된다.
- 동시성·교착·팝업 반복 회귀 테스트와 실제 LMS 확인 근거가 기록된다.

## 진행 상황 (2026-09-28)

**슬라이스 1 구현: 감지·중복 방지·자동 저장 제출 기반.**

- `src/core/services/detection.py`: 신규 영상 선택·중복 키 기록 순수 로직.
- `src/web/autoplay.py` `AutoDetect`: 설정의 수동 토글·주기·선택 과목을 읽고 기존 courses 조회 큐/캐시를
  재사용해 **한 번에 한 단계만**(과목 목록 갱신 → 과목 상세 갱신 → 신규 영상 제출) 수행한다. `service.lock`을
  짧게만 잡아 큐 간 대기 그래프를 만들지 않는다. `auto-play.json`에 감지 기록·제출·일시중지·마지막 실행을 보존한다.
- 설정: `auto_detect_enabled`, `auto_detect_interval_minutes`(기본 30), `auto_detect_courses`, `auto_save_scope`(download/full).
- API: `GET /auto-detect`, `POST /auto-detect/check`, `POST /auto-detect/resume`. 앱 수명 주기에서 15초 주기로 tick.
- UI: 처리 설정의 "자동 감지 · 자동 저장" 섹션(토글·주기·과목 ID·범위·상태·지금 확인·재개).
- 자동 저장은 설정 범위대로 기존 작업 큐에 제출하고 `auto:<key>` 멱등 키로 중복 제출을 막는다.
- 검증: `tests/test_autoplay.py` 6개(순수 로직·단계별 갱신·중복 방지·범위별 종단 단계·일시중지), 전체 67개 통과.

**남음:** 자동 재생(출석) 워커와 팝업 유형별 처리·3회 반복 일시중지, 재생 시간 기준, CDP 락 순서 확정, 실제 LMS 확인.

**선행 조사 (2026-09-28):** 실제 LMS로 재생 시작·인트로·팝업 DOM을 확인했다. 재생은
`.vc-front-screen-play-btn`(내부 commons 프레임) → 인트로(`intro.mp4`, 약 5초) → 실제 미디어 순이며,
이어보기·"재생 중" 팝업은 모두 `.confirm-msg-box`이고 `.confirm-msg-text` 내용으로 구분한다.
자세한 선택자·문구는 [DOM 조사 로그](../logs/2026-09-28-autoplay-dom-investigation.md)에 기록했다.
