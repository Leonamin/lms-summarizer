## 현재 진행도

계획 기록과 1단계 기능 조사·기술 계약·실제 LMS 로그인/CDP 검증을 완료했다. 2단계 공통 모델·설정·저장 분리를 완료했다. 3단계 영속 작업·독립 단계 실행기를 완료했다. 4단계 설치형 서비스 연결·중복 워커 정리·Linux 회귀와 번들 검증을 수행했다. macOS/Windows 빌드·실환경 기능 확인은 미완료이므로 4단계는 부분 완료다. 사용자 합의에 따라 4단계 잔여 검증은 설치형 출시 전 확인 항목으로 보류하고 5단계를 진행한다. 5단계 웹 최소 흐름·Docker 실행·재접속/재생성 복원을 완료했다. 6단계 LMS 과목·주차 조회·URL 입력, 모든 STT·요약 공급자 설정, 프롬프트, 작업 로그·서버 진단·업데이트 안내와 PC/모바일 화면을 웹에 대응했다. 실제 공급자 키·실제 강의 전체 처리·실제 LAN 기기는 7단계에서 검증했다. 7단계에서 대상 호스트(Ubuntu 26.04)의 실제 LMS 강의 전체 처리(다운로드→CPU STT→Gemini 요약)·취소·재시작 복구·백업/복원·업데이트·LAN/Tailscale 접속과 운영 문서를 확인했다. macOS/Windows 설치형 빌드(4단계 보류)와 Gemini 외 유료 공급자 실제 키는 미검증으로 남긴다. 7단계 이후 개선 작업으로 타이포그래피·UX/UI 개선과 신규 강의 감지·자동 재생·자동 저장을 8단계로 추가했다([ADR-004](../decisions/004-auto-play-and-ux-improvements.md), [자동 재생 상세 계획](auto-play-new-lectures.md)). 실제 작업과 단계별 완료 기준을 충족했을 때 체크한다.

## 갱신 규칙

체크 개수만으로 완료를 판단하지 않는다. 상세 계획의 완료 기준을 따르고 결과표에 진행 중·부분 완료·완료·보류와 검증 근거를 기록한다. 계정·환경이 없어 확인하지 못한 항목은 체크하지 않는다. 새 결정은 ADR과 로그에 기록한다.

전체 완료 시 상세 계획과 TODO의 결과를 logs에 보존하고 plans에서 정리하며 관련 링크도 함께 갱신한다.
