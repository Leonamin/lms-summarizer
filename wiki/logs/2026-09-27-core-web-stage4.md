# 4단계 설치형 공통 작업 서비스 연결

## 상태

**부분 완료.** 설치형 서비스 전환과 Linux 검증을 수행했다. macOS·Windows 빌드 및 실제 OS 동작은 이 Linux 세션에서 확인하지 못했으므로 4단계 전체 완료로 표시하지 않는다. 웹 제품 구현은 5단계에서 진행한다.

## 선행 수정 커밋

사용자가 수정한 작업 종료·설정 호환 회귀를 `b3ee490 fix: 작업 종료 및 설정 호환 회귀 수정`으로 커밋했다. 사용자 변경 5개 파일을 대상으로 기존 36개 테스트가 통과했다. 해당 커밋과 이후 4단계 작업은 구분한다.

## 설치형 실행 경로

- `src.desktop.main`이 GUI import 전에 `multiprocessing.freeze_support()`를 호출한다. PyInstaller 진입점도 동일하게 변경했다. 기존 `python -m src.gui.main`은 이 진입점을 경유한다.
- 앱 수명의 `DesktopRuntime`이 `JobService`와 이벤트 구독 스레드를 소유한다. Flet 화면은 공개 작업 상태를 읽고 제출·취소·재시도만 요청한다. 종료 시 화면 구독·강의 목록 워커를 정리하고 서비스를 닫는다.
- 설치형 관리 데이터는 기존 앱 데이터 디렉토리의 `runtime/` 아래에 저장한다. SQLite·입력·산출물·비밀 버전과 데스크톱 목적지/내보내기 기록을 구분한다. 웹 저장과 공유하지 않는다.
- 기존 계정·요약/STT 엔진·모델·엔드포인트·프롬프트·고급 설정을 제출 시 고정한다. 비밀번호·키·ReturnZero 자격 증명은 버전 저장소에 저장하며 공개 설정에는 참조만 전달한다. 설치형 faster-whisper의 `device/compute_type=auto` 기본값을 유지한다.
- 원본 파일은 서비스에 복사하며 사용자 원본을 삭제하지 않는다. 완료 산출물은 기존 다운로드 설정 경로 아래 작업·시도 UUID별 폴더로 내보낸다. 덮어쓰기 충돌을 피하고 원문·요약·프롬프트와 보존 설정에 따른 원본을 제공한다.
- 기존 JSON 이력의 알 수 없는 설정·이전 이력을 보존하고 작업·시도 ID로 중복 이력을 방지하고 기존 이력의 원본 LMS URL·다운로드 이름을 유지한다. 기존 설정 변경과 이력 추가가 같은 JSON 잠금을 사용해 동시에 저장해도 서로의 변경을 유실하지 않도록 했다. 내보내기 실패는 공통 작업 성공 상태를 바꾸지 않으며 결과 버튼으로 다시 시도할 수 있다.
- 클립보드 복사·챗봇/폴더 열기는 부모 데스크톱 프로세스에서만 수행한다. 프롬프트 생성은 `manual_ready`로 표시하고 자동 요약과 구분한다. 호스트 동작 실패는 저장된 프롬프트를 남기고 로그에 표시하며 다시 복사할 수 있다.
- 화면은 재시작된 작업을 복원하고 단계별 대기·실행 수, 취소·재시도·결과·프롬프트 복사 버튼을 제공한다. 오래된 상태 알림은 최신 revision을 덮어쓰지 않는다. 작업 목록 높이를 제한하고 스크롤한다.
- 실제 화면 검증 중 로그 자동 스크롤이 coroutine 객체를 `run_task`에 전달하던 오류를 발견했다. async 함수를 예약하고 `scroll_to`를 await하도록 수정했다.

## 중복 처리기 정리

`rg`로 활성 참조를 확인한 뒤 Flet의 `QueueManager`, `ProcessingWorker`, `ItemProcessor` 호환 shim, 사용되지 않는 `QueuePanel`을 삭제했다. 코어의 이전 순차 `ItemProcessor`도 제품 호출자가 없어 삭제하고, 해당 테스트를 현재 `PipelineExecutor` 경계 검증으로 전환했다. 강의 목록 조회에 사용되는 `CourseListWorker`는 유지한다. LMS 로그인·CDP 처리 흐름은 변경하지 않았다.

## 검증

- Python unittest: 데스크톱 통합·화면 회귀를 포함해 **44개 통과**. 실제 spawn 프로세스로 설정 고정, 원본 보존, 취소/재시도, 복원, 이력 중복 방지, 내보내기 오류 후 복구, UI 상태 순서와 비동기 로그 스크롤을 검증했다.
- Linux PyInstaller: spec 빌드 성공. 생성된 `dist/LMS-Summarizer/LMS-Summarizer --core-smoke` 실행으로 네 spawn 워커, 생산용 클립보드 단계와 산출물·정상 종료를 확인했다. 이 진단은 실제 LMS·모델 다운로드·유료 API 호출 없이 실행한다.
- macOS/Windows 릴리스 워크플로와 Windows 로컬 빌드 스크립트에 번들 `--core-smoke` 검증을 추가했다. Windows console=False에서도 JSON 결과 파일과 프로세스 종료 코드로 실패를 판정한다. 워크플로를 실제 실행하거나 릴리스하지 않았다.
- 실제 Flet 컨트롤을 localhost의 임시 웹 렌더러로 열어 확인했다. 합성 작업을 취소 상태로 복원하고 재시도 버튼을 눌러 `프롬프트 준비 완료`·결과/복사 버튼·저장 로그로 전환되는 것을 확인했다. 이 임시 화면은 제품 웹 대시보드가 아니다. 호스트 동작은 테스트 어댑터로 대체했다.
- 화면 캡처: `/tmp/lms-stage4-before.png`, `/tmp/lms-stage4-complete.png` (임시 검증 파일이며 저장소에 포함하지 않는다).

## 후속 진행 합의

사용자는 4단계를 부분 완료로 남기고 5단계 웹 구현을 진행하기로 했다. 아래 잔여 항목은 설치형 출시 전 검증으로 보류하며 완료 체크를 하지 않는다.

## 남은 검증

- macOS와 Windows의 실제 PyInstaller 빌드 및 네 spawn 워커 실행.
- 대상 OS Flet 네이티브 창의 파일 선택·종료, 실제 클립보드·브라우저·파일 탐색기 동작.
- 실제 계정 LMS 목록·다운로드→변환→STT→요약 전체 회귀, 공급자별 실제 키 호출, Windows GPU와 macOS 저장 권한 회귀. 공통 서비스의 합성 테스트와 번들 클립보드 진단을 이 검증의 대체 완료로 취급하지 않는다.
