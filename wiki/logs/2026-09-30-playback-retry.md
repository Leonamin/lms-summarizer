# 재생 재시도

## 배경

`고급웹프로그래밍 5주차` 재생 기록이 `completed/attended`인데 실제 LMS에는 진도·출석이 없었다. 진단 결과
강사가 **5주차 영상을 재업로드**해 항목 ID가 바뀌었고(3401032 → 3402236), 새 항목은 `00:00 / 44:27`,
출석 "미결"이었다. 기존 기록은 삭제된 항목을 가리켰다.

이 과정에서 구조적 문제를 확인했다. `seen`에 등록된 강의는 자동 감지가 영구히 건너뛰고, UI/API에 재생
재시도가 없어 **컨테이너 재시작 등으로 중단된 재생이 미출석 상태로 방치**됐다(미출석 기록 10건).

## 구현

- `PlaybackQueue.retry(context, record_id)` — 실패/중단 기록을 `queued`로 되돌려 재적재. 출석 완료 건은
  `already_attended`(409)로 거부, 진행 중이면 no-op. `find(context, url)`로 URL별 최신 기록을 조회.
- `POST /playback/{id}/retry` API.
- 감지 정책: `select_retry_videos()`가 **`seen`이어도 미출석(completion≠completed, attendance 미인정)이면
  재시도 대상**으로 포함. `auto-play.json`의 `attempts`(URL별) 카운터로 **최대 3회**(`PLAYBACK_RETRY_LIMIT`)
  제한해 무한 반복을 막고, 이미 진행 중(queued/running)이면 중복 적재하지 않는다.
- UI: 재생 이력의 실패/중단 항목에 `다시 재생` 버튼.

## 운영

- 감지 주기를 24시간 → 30분으로 조정.
- 미출석 재생 10건 중 이미 출석된 7건을 제외하고 3건 재시도, 자동 감지가 `4주차_03_UI컴포넌트`까지 추가 감지.
- 재업로드된 새 5주차(3402236, 44:27)를 강제 감지로 큐에 적재. 총 5건 약 123분 순차 재생.
