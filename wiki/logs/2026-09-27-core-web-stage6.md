# 6단계 전체 기능 웹 대응·검증

## 결과와 검증 범위

**6단계 완료.** 기존 활성 기능의 웹 대응과 구현 위치·검증 근거를 아래에 연결했다.
실제 LMS 과목·강의 조회는 제공된 계정으로 Docker Chrome에서 확인했다. 공급자의 유료 API는
호출하지 않았으며 설정 전달·자격 증명 선택·어댑터 대체 검증과 기존 합성 HTTP 검증으로 구분한다.
실제 강의 전체 다운로드→로컬 Whisper 추론→유료 요약, 실제 LAN 기기와 장시간 운영은 7단계 잔여다.
4단계 설치형 OS 검증 보류는 유지한다. 5단계는 `4c6faf4`로 커밋한 상태에서 진행했다.

## 구현과 정책

- `src/core/services/courses.py`의 영속 조회 큐와 캐시는 소유자·학번·비밀번호 버전 경계를 갖는다.
  과목/주차 캐시는 24시간 만료하며 교체한 계정의 기존 캐시를 반환하지 않는다. 같은 활성 조회를
  중복 요청하면 같은 ID를 돌려준다. 활성 조회 한도는 20개다.
- `JobService`의 다운로드 슬롯에서 조회와 다운로드를 번갈아 배정한다. 브라우저를 동시에 조작하지
  않으며 실행 중 조회는 재시작 시 interrupted, queued 조회는 복원한다. 조회 시간 초과/워커 종료도
  슬롯 프로세스를 회수·교체한다. 조회가 참조하는 비밀은 실행이 끝날 때까지 삭제를 막는다.
- `PipelineExecutor`는 기존 `CourseScraper`와 시스템 Chrome을 사용한다. 로그인/CDP 추출 순서는
  수정하지 않았다. 과목 조회와 주차 상세의 enum/URL/선택 가능 상태를 DTO로 변환한다.
- 과목 학기·즐겨찾기 필터, 주차 영상 전체 선택·선택 해제, 시간·출석·완료·예정 상태, 캐시 나이와
  갱신 상태, URL 일괄·추가 제출 및 종료 단계 선택을 제공한다. 예정/비영상은 선택하지 못한다.
- URL 제출 응답이 유실되면 원래 URL·설정 revision·종료 단계·요청 키를 유지한다. 설정 화면으로
  이동하고 설정을 저장한 후에도 같은 키로 확인하여 중복 제출을 막는다.
- `src/core/catalog.py`가 기존 공급자·모델 레지스트리와 공통 프롬프트 정보를 제공한다.
  모델 목록을 새 최신 목록으로 교체한 것은 아니며 모델 ID 직접 입력도 가능하다.
- 설정 화면에서 모든 STT/요약 엔진·모델·선택적 호환 엔드포인트·공급자별 키·ReturnZero의 별도
  Client ID/Secret, STT 장치·정밀도·언어·힌트·VAD·반복 제거와 HTTP 요청 제한 시간을 편집한다.
  임의 STT 파라미터·비밀 혼입·잘못된 엔드포인트/값은 웹 DTO에서 거부한다.
- 구조화 요약 모드·분야·직접 과목명·사용자 지시문·초기화·미리보기는 코어 생성기를 사용한다.
  비밀 저장 도중 설정 저장을 잠시 막고, revision 충돌 때 작성 중인 설정을 보존한다.
- 작업 로그는 owner/job/attempt/stage 경계를 갖는 안전한 이벤트만 읽는다. 원문·비밀번호·키·서명
  URL·서버 경로를 로그로 반환하지 않는다. UI는 cursor로 이어서 조회하고 최근 200개를 표시한다.
- 서버 진단은 버전·SQLite·Chrome·남은 용량·supervisor·실행 모드·볼륨·보관 정책을 제공한다.
  수동 릴리즈 확인은 GitHub의 고정 저장소를 조회하며 네트워크 실패를 화면에 표시한다.
  앱 자동 교체는 하지 않고 백업 후 Compose 업데이트 절차를 안내한다.
- `LMS_CHROME_PATH`/`LMS_CHROME_HEADLESS`는 서버 설정이다. 화면 모드일 때 CLI가 Xvfb를 소유하고
  정리한다. 서버 Chrome 설정 변경 시 새 제출 스냅샷을 만들고 기존 스냅샷은 유지한다.
- 강의 출석 파서에서 공통 `attendance_status` 클래스 자체를 출석으로 인식하던 오류를 수정했다.
  실제 상태 토큰을 구분하고 결석·지각·출석·정보 없음에 회귀 테스트를 추가했다.

## 검증 기록

- unittest 전체 **61개 통과**: 기존 51개와 단계 6 신규 10개. 신규 검증은 모든 공급자 설정/비밀 선택,
  프롬프트 일치, DTO 검증, 계정 캐시/만료, 조회·다운로드 직렬 실행, 로그 cursor와 비밀 미노출,
  조회 실패/timeout/재시작/대기 복원, 서버 Chrome 설정 스냅샷 갱신과 출석 파서다.
- TypeScript 검사·Vite 프로덕션 빌드 통과. 최종 Docker 이미지 빌드·Compose 구성 확인.
- 읽기 전용 실제 LMS 확인: Docker 시스템 Chrome headless로 과목 **11개**, 제공된 강의의 과목
  상세 **15주차·영상 15개** 조회. 계정·비밀번호·강의 제목·URL을 출력/로그/위키에 기록하지 않았다.
- Docker 화면 진단: `LMS_CHROME_HEADLESS=false`, UID 10001, Xvfb :99에서 시스템 Chrome headed
  실행과 data 페이지 열기 성공; `/system`에서 SQLite 3.53.1·healthy/headed/Chrome 설치 확인.
- agent-browser `http://127.0.0.1:8016`에서 합성 과목·강의 갱신→예정/비영상 2개 선택 불가→영상 전체
  선택→다운로드 종료 작업 제출→완료/결과 다운로드를 확인했다. 실제 LMS 개인정보 화면은 캡처하지 않았다.
- URL POST 응답을 성공 후 유실시킨 브라우저 검증에서 설정 화면 이동·저장 후 동일 요청 재확인:
  작업 수는 기존 1개+새 작업 1개인 **2개**를 유지했다. 자동으로 별도 작업을 만들지 않았다.
- 1280px PC와 390px 모바일에서 작업/설정/주차 선택·로그·진단을 확인했다. 모바일 scrollWidth=innerWidth=390,
  설정 재진입 시 비밀번호 입력 값은 비어 있다. 실제 휴대폰 LAN은 7단계 대상이다.
- 캡처는 `/tmp/lms-stage6-desktop-final.png`, `/tmp/lms-stage6-mobile-final.png`,
  `/tmp/lms-stage6-settings-mobile-final.png`이며 Git에 넣지 않는다. 테스트 로그·임시 서버도 저장소 밖이다.

## 남은 운영 검증

실제 LAN PC/휴대폰·장시간 실행·디스크 부족·백업/복원·업데이트와 종료 절차를 확인한다.
