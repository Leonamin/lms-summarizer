# 작업실 UI·UX 개편 기록

2026-10-04. 운영 웹을 읽기 전용으로 조사하고 로컬 프런트엔드를 개편했다.
운영 서버의 작업·설정·데이터를 변경하거나 배포하지 않았다.

## 관찰한 문제

| 우선순위 | 실제 관찰 | 사용자 영향 | 적용한 변경 |
| --- | --- | --- | --- |
| 높음 | 1864×923에서 작업 목록이 문서 상단 1,100px 아래에 시작 | 기존 결과를 확인하려 해도 등록 폼 두 개를 지나야 함 | 가져오기를 별도 화면으로 분리하고 목록·상세를 기본 화면에 배치 |
| 높음 | 390×844에서 목록 1,792px, 상세 3,311px 아래 시작 | 행 선택 후 상세를 찾기 위해 긴 페이지를 이동 | 좁은 화면에서 목록/상세 전환, 목록 복귀·브라우저 뒤로가기 지원 |
| 중간 | 처리 중 0개여도 현황·단계 카드 7개가 상단 점유 | 실제 작업보다 집계에 먼저 시선이 감 | 상태 집계를 목록 필터로 통합, 단계별 집계는 필요할 때 펼침 |
| 중간 | 동일한 강의명으로 표시되는 작업이 있음 | 어떤 과목의 결과인지 구분하기 어려움 | 과목·주차를 행의 두 번째 줄에 표시하고 검색에 포함 |
| 중간 | 자동 재생 이력이 일반 처리 목록의 머리글과 행 사이에 위치 | 서로 다른 큐를 하나의 표로 오인하기 쉬움 | 재생 이력을 페이지네이션 뒤 별도 영역으로 이동 |
| 중간 | 완료 작업에서도 단계·시도 정보가 결과 앞에 크게 노출 | 요약 읽기까지 탐색 비용 증가 | 완료 시 처리 정보를 접고 요약/원문·전체 보기를 우선 노출 |

관찰은 실제 화면·DOM 위치·로컬 컴포넌트 코드를 함께 확인한 결과다. 사용자 행동 분석이나 사용성 실험을 수행한 것은 아니다.

## 원칙과 레퍼런스

1. **자주 필요한 정보 우선, 부가 정보는 요청 시 공개.**
   [NN/g — Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)는 핵심 옵션을 우선 보이고 복잡하거나 덜 쓰는 기능을 다음 단계로 미루는 원칙을 설명한다.
   단계 집계와 완료 작업의 처리 이력을 접는 데 적용했다. 가져오기는 중요한 기능이므로 상단 버튼과 독립 메뉴에 명시적으로 남겼다.
2. **목록 탐색과 상세 읽기의 관계를 화면 폭에 맞춰 유지.**
   [Material 3 — Canonical layout examples](https://m3.material.io/foundations/layout/canonical-examples/overview)는 목록–상세와 주/보조 패널을 대표 레이아웃으로 설명한다.
   넓은 화면은 목록 옆 상세, 좁은 화면은 한 번에 한 패널을 보여주는 구조로 적용했다. 1180px 기준은 현재 앱의 레일·최소 목록 너비에 맞춘 결정이다.
3. **상세를 확인한 뒤에도 탐색 맥락 유지.**
   [Linear — Peek preview](https://linear.app/docs/peek)는 목록·보드에서 항목 상세를 빠르게 확인하는 제품 사례다.
   검색·정렬·페이지·선택 상태를 보존하고 긴 결과는 기존 전체 보기로 여는 데 참고했다. Linear의 UI나 단축키 전용 진입을 복제하지 않았다.

이 자료들이 LMS의 사용 빈도나 최적 화면 수를 입증하는 것은 아니다. 등록·처리 관리·읽기의 목적 차이와 운영 화면에서 관찰한 공간 배분을 바탕으로 설계에 적용했다.

## 화면 구조와 동작

- `#workspace`: 작업 상태 필터, 접힌 단계별 집계, 작업 목록·선택 상세.
- `#import`: 과목·주차 / URL 입력 / 파일 업로드 중 한 가지 폼. 메뉴·방식 전환 중 입력 유지.
- `#settings`: 처리 설정 및 서버 진단.
- 1180px 이하: 행 선택 시 `#workspace/<job-id>` 상세. 목록 복귀와 브라우저 뒤로가기로 검색·정렬·페이지·선택·포커스 복원.
- 완료 작업은 처리 단계를 기본 접힘으로, 실패·진행 작업은 기본 펼침으로 표시.
- 상태/검색 결과에서 제외된 항목이 상세에 남지 않도록 선택을 동기화.
- 작업 제출 후 필터·검색을 초기화하고 해당 페이지·행으로 이동. 숨겨진 폼에서 제출되더라도 목록이 표시된 뒤 포커스와 스크롤을 적용.
- 재생 이력의 연결 작업으로 이동할 때 기존 검색/필터와 다른 페이지에 있던 항목도 찾아 표시.
- LMS와 파일의 종료 단계 선택은 각각 유지. 파일 업로드에는 사용할 수 없는 다운로드 단계 옵션 제거.
- 새로고침은 현재 화면을 유지하지만 미제출 입력·목록 필터의 영구 저장은 제공하지 않는다.

## 구현과 부수 수정

기존 Pretendard·색상·radius·공용 Dropdown·결과 전체 보기 dialog를 유지했다.
표시만 바꾸며 백엔드 처리·재시도·자동 재생 API는 변경하지 않았다.

기존 체크아웃은 `frontend/src/lib/format.ts`, `stageIcons.ts`가 누락되어 빌드되지 않았다.
두 파일을 서버의 상태·공급자 ID와 사용처에 맞춰 복구하고 Python용 `lib/` Git 제외 규칙에 프런트엔드 예외를 추가했다.
HTTP LAN에서도 idempotency UUID를 만들 수 있도록 `crypto.getRandomValues` 대체 경로를 포함했다.

## 검증

운영 조사와 로컬 검증은 구분한다. 로컬 UI 검증 서버는 **합성 데이터와 가짜 제출 응답**을 사용하며 실제 강의를 처리하지 않는다.

| 항목 | 결과 |
| --- | --- |
| TypeScript 검사 + Vite production build | 통과. 500KB 초과 JS 번들 경고는 남음 |
| Node 회귀 검사 3개 | 통과: HTTP UUID 대체 경로, 상태 분류, 공급자 ID·출석 라벨 |
| 데스크톱 1864×923 / 1440×900 | 목록 시작 256px. 목록·상세가 첫 화면에 보임 |
| 태블릿 768×1024 / 모바일 390×844 | 가로 넘침 없음. 모바일 목록 시작 450px |
| 상태 필터·과목/주차 검색·빈 검색 결과 초기화 | 확인 |
| 필터 변경 시 상세 선택 일치 | 확인 |
| 입력 방식·메뉴 이동 후 URL 입력 유지 | 확인 |
| 합성 URL 제출 후 새 작업 선택·페이지·스크롤·포커스 | 확인. 목록 하단에서 시작한 경우도 확인 |
| 미완료 재생 → 필터 이력 → 연결 작업의 다른 페이지 | 확인 |
| 모바일 상세 → 목록 / 브라우저 뒤로가기 | 검색어·선택·포커스 유지 확인. 해시 없는 최초 주소도 확인 |
| 전체 보기 dialog → Escape | 닫힘 및 원래 버튼으로 포커스 복귀 확인 |
| 빈 작업실·초기 로딩·연결 실패 | 가져오기 진입, 스켈레톤, 다시 연결 버튼 확인 |
| 브라우저 콘솔 | 최종 검증에서 오류·경고 없음 |
| DESIGN.md lint | 오류 0, 경고 10. 기존 의미색 대비/미참조 토큰 경고. diff에서 토큰 변경 없음 |
| 정적 디자인 스캔 | 기존 CSS 토큰·원시 색상 관련 경고. 자동 경고를 디자인 결함 수로 해석하지 않음 |
| 기존 Python 웹 API 테스트 20개 | 15개 통과. Stage6의 5개는 정리 단계의 `os.killpg` PermissionError로 오류. 전체 통과 아님 |

위 위치 수치는 운영 29개 작업 화면과 로컬 합성 작업 화면에서 측정한 레이아웃 위치다. 처리 속도나 실제 사용자 생산성 개선 수치가 아니다.

## 남은 검증

- 운영 배포 및 배포된 프런트엔드 확인.
- 실제 LMS 가져오기·파일 업로드·외부 AI 처리의 새 UI 경유 쓰기 E2E. 이번 운영 조회에는 쓰기 동작을 수행하지 않았다.
- Python Stage6 워커 정리 권한 오류의 별도 원인 분석.
- 접근성 전체 감사나 사용자 사용성 실험은 수행하지 않았다.
